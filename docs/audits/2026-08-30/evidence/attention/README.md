## Reproduction and limits

It executes only original pure/host functions needed to inspect real backend flags and counts. The audit's W1-090 suggestion that changing to a cooperative/block-scope `memcpy_async` is sufficient to establish TMA is not used as proof. NVIDIA distinguishes elementwise LDGSTS and bulk TMA; actual lowering still requires compilation/inspection. Similarly, the CPU-only build lacks `Stream.priority_range`, but official PyTorch 2.8's CUDA C++ binding exposes it. That nearby suspicion was refuted before any change to the valid helper.

The four existing persistent-decode pair tolerances are retained. They are not new measured accuracy bounds. The complete-output and per-sequence omission checks are additional independent requirements. Other newly authored CUDA numeric gates use Torch's dtype defaults or exact copy/token comparison; a future failed numerical gate must be investigated, not weakened to manufacture a pass. No pre-existing expectation JSON or historical performance artifact was overwritten.
